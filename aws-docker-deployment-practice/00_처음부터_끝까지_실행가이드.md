# 처음부터 끝까지 실행 가이드

이 파일 하나만 위에서 아래로 따라가면 로컬 Build·Docker Hub Push·EC2 배포까지 진행할
수 있습니다. 명령 위의 **실행 위치**를 반드시 확인합니다.

## 준비 값

실습 전에 다음 값을 메모해 둡니다.

```text
Docker Hub ID: hyunport
Docker Image Version: 1.0.0
EC2 OS: Ubuntu
EC2 사용자: ubuntu
PEM 파일: Agentkey.pem
EC2 Public IP: <PUBLIC_IP>
EC2 작업 폴더: /home/ubuntu/test
```

`<PUBLIC_IP>`는 명령에 그대로 쓰지 말고 실제 EC2 Public IPv4로 바꿉니다. 실제 API Key와
PEM 내용은 문서·채팅·Git에 올리지 않습니다.

---

## 1. 로컬 Docker 확인

**실행 위치: Windows PowerShell**

Docker Desktop을 실행한 뒤 프로젝트 폴더로 이동합니다.

```powershell
cd "C:\Users\Playdata\Desktop\새 폴더\aws-docker-deployment-practice"
docker version
docker compose version
```

Compose 설정을 검사합니다. 메시지 없이 끝나면 정상입니다.

```powershell
docker compose config --quiet
```

## 2. Backend·Frontend Image Build

**실행 위치: Windows PowerShell / 프로젝트 최상위**

```powershell
docker compose build backend frontend
docker image ls
```

다음 두 Image를 확인합니다.

```text
simple-multi-llm-app-backend:latest
simple-multi-llm-app-frontend:latest
```

Image 이름만 PowerShell에 입력하면 명령이 아니므로 오류가 납니다. 항상 `docker tag`,
`docker push` 같은 명령 뒤에 Image 이름을 사용합니다.

## 3. Docker Hub Tag·Push

**실행 위치: Windows PowerShell**

```powershell
docker tag simple-multi-llm-app-backend:latest hyunport/simple-multi-llm-backend:1.0.0
docker tag simple-multi-llm-app-frontend:latest hyunport/simple-multi-llm-frontend:1.0.0
docker image ls hyunport/*
```

Docker Hub에 로그인하고 Push합니다.

```powershell
docker login
docker push hyunport/simple-multi-llm-backend:1.0.0
docker push hyunport/simple-multi-llm-frontend:1.0.0
```

각 Push 마지막에 `digest: sha256:...`가 나오면 성공입니다.

## 4. EC2 생성과 보안 그룹

**실행 위치: AWS Console**

1. Ubuntu EC2 Instance를 생성합니다.
2. 새 PEM을 만들지 않고 수업에서 사용한 기존 PEM을 선택합니다.
3. Public IPv4를 기록합니다.
4. 해당 Instance의 `보안` 탭에서 연결된 보안 그룹을 엽니다.
5. **인바운드 규칙 편집**을 선택합니다. `아웃바운드 규칙 편집`과 혼동하지 않습니다.

### 인바운드 규칙

외부에서 EC2로 들어오는 연결을 허용하는 규칙입니다. 다음 세 줄을 추가합니다.

| 유형 | 프로토콜 | 포트 범위 | Source 유형 | Source 값 | 설명 |
| --- | --- | ---: | --- | --- | --- |
| SSH | TCP | 22 | 내 IP | 현재 공인 IP `/32` | 관리자 SSH 접속 |
| 사용자 지정 TCP | TCP | 8000 | 내 IP | 현재 공인 IP `/32` | FastAPI Health 확인 |
| 사용자 지정 TCP | TCP | 8501 | 내 IP | 현재 공인 IP `/32` | Streamlit 화면 접속 |

AWS Console에서 `내 IP`를 선택하면 `121.170.161.1/32` 같은 값이 자동으로 들어갑니다.
`/32`는 그 공인 IP 하나만 허용한다는 뜻입니다. 교육장·집·모바일 네트워크가 바뀌면 공인
IP도 바뀔 수 있으므로 SSH가 갑자기 안 될 때 Source의 `내 IP`를 다시 갱신합니다.

Redis `6379`와 PostgreSQL `5432`는 인바운드에 추가하지 않습니다. 같은 EC2 내부의
Container끼리 통신하므로 인터넷에 공개할 필요가 없습니다.

### 아웃바운드 규칙

EC2에서 인터넷으로 나가는 연결을 제어합니다. `apt install`, Docker Image Pull, 외부 LLM
API 호출에 필요하므로 수업에서는 기본 규칙을 유지합니다.

| 유형 | 프로토콜 | 포트 범위 | 대상 |
| --- | --- | --- | --- |
| 모든 트래픽 | 전체 | 전체 | `0.0.0.0/0` |

아웃바운드 화면에 SSH·8000·8501을 추가하는 것이 아닙니다. 기본 `모든 트래픽 →
0.0.0.0/0` 규칙을 삭제하거나 위 세 포트로 제한하면 패키지 설치와 Docker Hub Pull이
실패할 수 있습니다. IPv6를 사용하는 환경에 기본 `::/0` 규칙이 있다면 수업 정책에 따라
그대로 유지합니다.

## 5. SSH 접속

**실행 위치: Windows PowerShell / PEM 파일이 있는 폴더**

```powershell
cd "C:\Port_수업자료\docker_AWS"
ssh -i ".\Agentkey.pem" ubuntu@<PUBLIC_IP>
```

처음 접속할 때 대상 IP가 본인 EC2와 일치하는지 확인하고 지문 질문에 `yes`를 입력합니다.
접속 후 프롬프트가 `ubuntu@...:~$`로 바뀌면 이후 명령은 EC2 Ubuntu에서 실행합니다.

## 6. EC2에 Docker·Compose 설치

**실행 위치: EC2 Ubuntu**

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 git curl
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
exit
```

**실행 위치: Windows PowerShell**

그룹 권한 적용을 위해 다시 접속합니다.

```powershell
ssh -i ".\Agentkey.pem" ubuntu@<PUBLIC_IP>
```

**실행 위치: EC2 Ubuntu**

```bash
docker info
docker compose version
docker run --rm hello-world
```

권한 오류가 계속되면 `sudo docker info`로 서비스 상태를 확인하되, 로그인과 Compose는
서로 같은 권한 방식으로 실행합니다.

## 7. Redis 설치·확인

**실행 위치: EC2 Ubuntu**

이미 같은 이름의 Container가 있는지 먼저 확인합니다.

```bash
docker ps -a --filter name=aidevs-redis
```

아무것도 없다면 한 번만 생성합니다.

```bash
docker run -d \
  --name aidevs-redis \
  -p 6379:6379 \
  -v aidevs-redis-data:/data \
  redis:7 \
  redis-server --appendonly yes
```

이미 존재하지만 중지 상태라면 새로 만들지 않고 시작합니다.

```bash
docker start aidevs-redis
```

확인합니다.

```bash
docker ps --filter name=aidevs-redis
docker exec aidevs-redis redis-cli PING
```

기대 응답은 `PONG`입니다.

## 8. PostgreSQL·pgvector 설치·확인

**실행 위치: EC2 Ubuntu**

```bash
docker ps -a --filter name=aidevs-pgvector
```

아무것도 없다면 한 번만 생성합니다. 수업 EC2에서는 Host Port를 `5432`로 사용합니다.

```bash
docker run -d \
  --name aidevs-pgvector \
  -p 5432:5432 \
  -e POSTGRES_DB=agent_db \
  -e POSTGRES_USER=agent_user \
  -e POSTGRES_PASSWORD=agent_pwd \
  -v aidevs-pgvector-data:/var/lib/postgresql/data \
  pgvector/pgvector:pg16
```

이미 존재하지만 중지 상태라면 시작합니다.

```bash
docker start aidevs-pgvector
```

준비 상태를 확인합니다.

```bash
docker exec aidevs-pgvector pg_isready -U agent_user -d agent_db
```

결과에 `accepting connections`가 표시되어야 합니다.

## 9. Database Schema 설치

**실행 위치: EC2 Ubuntu**

PostgreSQL에 접속합니다.

```bash
docker exec -it aidevs-pgvector psql -U agent_user -d agent_db
```

프롬프트가 `agent_db=#`로 바뀌면 다음 SQL 전체를 붙여넣습니다.

```sql
CREATE SCHEMA IF NOT EXISTS simple_multi_llm;

CREATE TABLE IF NOT EXISTS simple_multi_llm.notes (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    message VARCHAR(500) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS simple_multi_llm.chat_messages (
    id BIGSERIAL PRIMARY KEY,
    session_id VARCHAR(100) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('user', 'assistant')),
    content TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_chat_messages_session
ON simple_multi_llm.chat_messages (session_id, id);
```

테이블을 확인하고 종료합니다.

```sql
\dt simple_multi_llm.*
\q
```

## 10. 로컬 배포 환경파일 준비

**실행 위치: Windows PowerShell / 프로젝트 최상위**

```powershell
cd "C:\Users\Playdata\Desktop\새 폴더\aws-docker-deployment-practice"
Copy-Item .env.example .env
notepad .env
```

다음 값을 확인합니다. API Key는 사용하는 Provider만 실제 값으로 입력합니다.

```dotenv
POSTGRES_USER=agent_user
POSTGRES_PASSWORD=agent_pwd
POSTGRES_DB=agent_db
DATABASE_URL=postgresql://agent_user:agent_pwd@host.docker.internal:5432/agent_db
REDIS_URL=redis://host.docker.internal:6379/0

OLLAMA_ENABLED=false

BACKEND_IMAGE=hyunport/simple-multi-llm-backend:1.0.0
FRONTEND_IMAGE=hyunport/simple-multi-llm-frontend:1.0.0
```

`.env`는 Git이나 제출물에 포함하지 않습니다.

## 13. EC2에서 파일과 권한 확인

```bash
cd ~/test

```

`cat .env`로 출력하지 않습니다.

## 14. EC2 Docker 로그인과 Pull 배포

**실행 위치: EC2 Ubuntu**

```bash
docker login
docker compose -f compose.release.yml config --quiet
docker compose -f compose.release.yml pull
docker compose -f compose.release.yml up -d
docker compose -f compose.release.yml ps
```

Docker Hub 저장소가 공개라면 Pull에 로그인이 필수는 아니지만, 수업에서는 인증 문제와
Pull 제한을 줄이기 위해 로그인합니다. `backend`, `frontend`가 실행되어야 합니다.

## 16. 오류 확인 순서

삭제부터 하지 말고 다음 순서로 확인합니다.

**실행 위치: EC2 Ubuntu**

```bash
docker ps -a
docker compose -f compose.release.yml ps
docker compose -f compose.release.yml logs --tail=100 backend
docker compose -f compose.release.yml logs --tail=100 frontend
docker logs --tail=100 aidevs-redis
docker logs --tail=100 aidevs-pgvector
```

자주 확인할 항목:

```text
pull access denied   → Image 이름·Tag·Docker 로그인 확인
connection refused  → Redis·DB 실행 상태와 Port 확인
permission denied   → Docker 그룹 적용 여부와 재접속 확인
8501 접속 실패      → Frontend 상태와 EC2 보안 그룹 확인
DB 테이블 오류      → simple_multi_llm Schema와 Table 확인
```

## 17. 애플리케이션 종료

**실행 위치: EC2 Ubuntu**

```bash
cd ~/test
docker compose -f compose.release.yml down
```

이 명령은 이 Compose의 Backend·Frontend만 종료합니다. Redis·PostgreSQL과 데이터 Volume은
임의로 삭제하지 않습니다. 전체 실습이 끝나면 AWS Console에서 EC2·EBS·Elastic IP의 비용
발생 여부를 확인합니다.
