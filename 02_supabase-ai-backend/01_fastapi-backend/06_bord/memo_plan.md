# 메모장 기능 기획서

## 1. 개요
이 문서는 "게시"를 누르면 현재 날짜와 시간이 자동으로 저장되고, 사용자가 입력한 내용을 함께 보관하는 메모장 기능의 전체 기획을 정리한 문서입니다.

첫 화면에서는 저장된 메모가 액자처럼 순서대로 나열되어야 하며, 각 메모를 클릭하면 상세 내용을 열어서 확인할 수 있어야 합니다.

## 2. 기획 목표
- 메모 작성 시점의 날짜와 시간을 자동 등록한다.
- 사용자가 원하는 내용을 자유롭게 입력할 수 있게 한다.
- 저장된 메모를 처음 화면에서 순서대로 보여준다.
- 각 메모를 열어 상세 내용을 확인할 수 있게 한다.
- 이후에는 수정, 삭제, 검색 기능으로 확장할 수 있게 구조를 잡는다.

## 3. 핵심 화면 구성

### 3-1. 첫 화면
- 메모 목록이 카드 또는 액자 형태로 배열된다.
- 최신 메모가 위에 오도록 정렬한다.
- 각 카드에는 다음 정보가 보인다.
  - 제목
  - 작성 날짜
  - 작성 시간
  - 짧은 미리보기 내용
- 카드 클릭 시 상세 보기로 이동하거나 모달이 열린다.

### 3-2. 메모 작성 화면
- 제목 입력칸
- 내용 입력칸
- 게시 버튼
- 게시 버튼을 누르면 현재 날짜와 시간이 자동으로 저장된다.

### 3-3. 메모 상세 화면
- 제목
- 작성 일시
- 전체 내용
- 수정 버튼
- 삭제 버튼

## 4. 데이터 설계

### 4-1. 메모 데이터 구조
```json
{
  "id": 1,
  "title": "오늘의 할 일",
  "content": "회의 준비, 문서 정리, 운동하기",
  "created_at": "2026-07-15 14:30:00"
}
```

### 4-2. 필드 설명
- `id`: 메모를 구분하는 고유 번호
- `title`: 메모 제목
- `content`: 메모 본문
- `created_at`: 게시 버튼 클릭 시 자동으로 저장되는 날짜와 시간

## 5. 기능 흐름

### 5-1. 게시 흐름
1. 사용자가 제목과 내용을 입력한다.
2. 게시 버튼을 누른다.
3. 시스템이 현재 날짜와 시간을 자동으로 만든다.
4. 입력값과 시간을 함께 저장한다.
5. 저장 완료 후 첫 화면의 목록에 즉시 반영한다.

### 5-2. 목록 조회 흐름
1. 첫 화면이 열리면 저장된 메모 목록을 불러온다.
2. 최신순으로 정렬한다.
3. 카드 형태로 나열한다.
4. 사용자가 원하는 메모를 클릭하면 상세 내용을 확인한다.

### 5-3. 상세 조회 흐름
1. 목록에서 메모를 선택한다.
2. 선택한 메모의 전체 정보를 불러온다.
3. 제목, 날짜, 시간, 내용을 보여준다.

## 6. API 기획

### 6-1. 메모 목록 조회
- `GET /memos`
- 전체 메모를 최신순으로 반환한다.

### 6-2. 메모 작성
- `POST /memos`
- 제목, 내용 입력값을 받고 현재 날짜와 시간을 자동 생성해서 저장한다.

### 6-3. 메모 상세 조회
- `GET /memos/{memo_id}`
- 선택한 메모 한 건의 상세 정보를 반환한다.

### 6-4. 메모 수정
- `PUT /memos/{memo_id}`
- 기존 메모의 제목과 내용을 수정한다.
- 작성 시각은 유지하거나, 정책에 따라 수정 시각을 별도로 둘 수 있다.

### 6-5. 메모 삭제
- `DELETE /memos/{memo_id}`
- 선택한 메모를 삭제한다.

## 7. 화면 정렬 규칙
- 기본 정렬은 최신 작성 순으로 한다.
- 목록은 한 줄 카드 또는 그리드 카드 형태로 보여준다.
- 카드의 크기는 일정하게 유지해 액자처럼 보이게 한다.
- 내용이 길면 카드 안에서는 일부만 보여주고, 상세 화면에서 전체를 확인한다.

## 8. 예외 처리
- 제목이 비어 있으면 게시를 막는다.
- 내용이 비어 있으면 게시를 막는다.
- 존재하지 않는 메모를 열려고 하면 안내 메시지를 보여준다.
- 삭제하려는 메모가 없으면 오류 메시지를 반환한다.
